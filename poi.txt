## 5. Quatrième étape : comprendre les principaux codes

Je vais t'expliquer les trois parties mathématiques les plus importantes.

### A. La loi de Poisson

Dans ton fichier `poisson.R`, tu trouveras :

```r
calculer_poisson <- function(lambda, k, cumul = FALSE) {

  if (!is.numeric(lambda) ||
      anyNA(lambda) ||
      any(lambda < 0)) {
    stop("Lambda doit être positif ou nul")
  }

  if (cumul) {
    stats::ppois(k, lambda)
  } else {
    stats::dpois(k, lambda)
  }
}
```

Cette fonction utilise directement les fonctions statistiques de R.

- `dpois()` calcule la probabilité d'obtenir exactement k événements.
- `ppois()` calcule la probabilité cumulée d'obtenir au maximum k événements.

Exemple :

```r
calculer_poisson(3, 2)
```

Elle calcule :

\[
P(X=2)=\frac{e^{-3}3^2}{2!}
\]

### B. La régression de Poisson

Dans `model.R`, tu trouveras :

```r
ajuster_modele_poisson <- function(
  data,
  formule,
  exposition_col = NULL
) {

  if (!is.null(exposition_col)) {

    formule <- stats::update.formula(
      formule,
      as.formula(
        paste(". ~ . + offset(log(", exposition_col, "))")
      )
    )
  }

  stats::glm(
    formule,
    data = data,
    family = stats::poisson(link = "log")
  )
}
```

Cette fonction permet à l'utilisateur de choisir les variables explicatives.

Exemple :

```r
modele <- ajuster_modele_poisson(
  donnees,
  accidents ~ pluie + vitesse
)
```

Tu peux aussi utiliser une variable d'exposition :

```r
modele <- ajuster_modele_poisson(
  donnees,
  accidents ~ pluie + vitesse,
  exposition_col = "trafic"
)
```

Cela permet de tenir compte du volume de circulation.

Attention : une variable d'exposition doit être strictement positive. Il faudra également vérifier la surdispersion et la qualité d'ajustement du modèle.

### C. Le système d'alerte

Dans `outputs.R` :

```r
generer_alerte <- function(data, count_col, seuil) {

  x <- data[[count_col]]

  niveau <- ifelse(
    x >= seuil,
    "Vigilance renforcee",
    "Surveillance habituelle"
  )

  recommandation <- ifelse(
    x >= seuil,
    "Examiner les circonstances et renforcer la surveillance",
    "Maintenir la surveillance"
  )

  cbind(
    data,
    niveau_vigilance = niveau,
    recommandation = recommandation
  )
}
```

L'utilisateur choisit le seuil correspondant à son analyse.

Le package produit ensuite une recommandation en fonction des résultats.

# 8. Ce que je veux que ton package puisse faire à terme

Voici le scénario d'utilisation final que nous allons viser :

```r
library(AccidentPoisson)

# 1. Importation des données
data <- readxl::read_excel("accidents.xlsx")

# 2. Analyse statistique
table_poisson(lambda = 3, k_max = 10)

# 3. Analyse des zones
zones <- analyser_zones(
  data,
  zone_col = "id_troncon"
)

# 4. Analyse temporelle
frequences <- aggreger_accidents(
  data,
  date_col = "date",
  group_cols = "id_troncon",
  periode = "mois"
)

# 5. Modélisation
modele <- ajuster_modele_poisson(
  data,
  nb_accidents ~ pluie + vitesse
)

# 6. Prédiction
predictions <- predire_accidents(
  modele,
  nouvelles_donnees
)

# 7. Diagnostic
diagnostiquer_surdispersion(modele)

# 8. Visualisation
visualiser_comptages(
  zones,
  "zone",
  "total_accidents"
)

# 9. Alertes
generer_alerte(
  zones,
  "total_accidents",
  seuil = 10
)
```

Il faudra naturellement utiliser un tableau agrégé pour la régression, puisque `nb_accidents` doit représenter un comptage par période et par tronçon, et non une ligne individuelle d'accident.
